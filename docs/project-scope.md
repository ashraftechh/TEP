# TEP-533 — توثيق نطاق المشروع وأهدافه العامة

> حالة الوثيقة: وثيقة تأسيسية معتمدة عند التوقيع، ملحقة بـ TEP-525. أي تغيير
> لاحق في النطاق يتطلب تحديث هذه الوثيقة أولًا، لا تعديل الكود مباشرة.

## 1. الخلفية

منصة تدريب تعاوني (Cooperative Training Platform) لجامعة يمنية، مبنية كتكييف
لمنصة مماثلة تخدم جامعات سعودية. النموذج الأولي المُسلَّم (React prototype)
والوثائق التخطيطية المرفقة تعود لتلك النسخة الأصلية، وتُستخدم هنا كمرجع
تصميمي (UI/UX وبنية البيانات المنطقية) لا كمصدر كود جاهز للنسخ.

المنتج مصمم كحل قابل للبيع (white-label) لأي جامعة يمنية: كل نشر يخدم جامعة
واحدة فقط، وهوية الجامعة (الاسم، الشعار) قابلة للتعديل من لوحة الإدارة دون
تعديل الكود.

## 2. الهدف العام

بناء نظام يدير دورة التدريب التعاوني الكاملة إلكترونيًا: من تسجيل الشركات
واعتمادها، مرورًا بنشر الفرص التدريبية وتقديم الطلاب عليها، وصولًا لتعيين
الطالب تدريبيًا، متابعته عبر التقارير، وتقييمه أكاديميًا في نهاية الدورة —
بديلاً عن أي عملية ورقية أو يدوية حالية.

## 3. المستخدمون والأدوار (7 أدوار)

| الدور | الوصف المختصر |
|---|---|
| Guest | زائر غير مسجل، يقدّم طلب تسجيل شركة أو يسجّل دخول |
| Student | طالب يقدّم على فرص التدريب ويتابع تدريبه؛ مرتبط بتخصص |
| Academic Supervisor | مشرف أكاديمي يراجع التقارير ويقيّم الطالب؛ مرتبط بقسم أكاديمي |
| Company Representative | ممثل شركة ينشر فرصًا ويراجع الطلبات؛ لا ارتباط أكاديمي |
| Training Coordinator / Admin | يدير الدورات، يعتمد الشركات، ينشر النتائج؛ مرتبط بقسم أكاديمي |
| Super Admin | صلاحيات تقنية كاملة، إدارة الأدوار والتكاملات؛ لا ارتباط أكاديمي |

## 4. الهيكل الأكاديمي

كلية ← قسم ← تخصص (تسلسل هرمي كامل). القسم الواحد قد يضم أكثر من تخصص.
الطالب يرتبط بتخصص؛ المشرف الأكاديمي ومنسق التدريب يرتبطان بقسم مباشرة.
ممثلو الشركات خارج هذا الهيكل تمامًا.

## 5. النطاق الوظيفي الأساسي (المسار الحرج)

```
تسجيل ومصادقة → اعتماد شركة → نشر فرصة → تقديم طالب → مراجعة/قبول
→ إنشاء تعيين تدريبي → تقارير الطالب ومراجعتها → تقييم أكاديمي ونشر النتيجة
```

بالإضافة إلى وحدات داعمة: المراسلة الداخلية، لوحات معلومات مختصرة لكل دور،
تصدير CSV أساسي، لوحة إدارة (Filament)، وسجل تدقيق (Audit Log) للقراءة فقط.

## 6. الحزمة التقنية

| الطبقة | التقنية |
|---|---|
| Backend | Laravel 13 / PHP 8.4 |
| قاعدة البيانات | MySQL |
| الواجهة العامة | React + TypeScript + Vite |
| لوحة الإدارة | Filament (Laravel/Livewire) |
| المصادقة | Laravel Sanctum (cookie SPA) — محلي (بريد/كلمة مرور) بالإضافة إلى SSO مؤسسي (Google وMicrosoft عبر Laravel Socialite)، مع تزويد تلقائي للحساب عند أول دخول SSO (JIT provisioning). الدخول المحلي متاح دائمًا كخيار بديل، حتى لمستخدم مرتبط بحساب SSO |


## 7. خارج النطاق حاليًا

| البند | السبب |
|---|---|
| تكامل SIS (نظام معلومات الطلاب الجامعي) | يتطلب بيانات وصول فعلية غير متوفرة بعد |
| دور Field Supervisor | قرار سياسة أكاديمية غير محسوم |
| تعدد ممثلي الشركة الواحدة | دعم أكثر من ممثل لكل شركة |

## 8. فروقات معتمدة عن النسخة السعودية الأصلية

1. MySQL بدل PostgreSQL
2. Filament بدل React للوحة الإدارة تحديدًا (الواجهة العامة تبقى React)
3. `spatie/laravel-translatable` بدل أعمدة `_ar`/`_en` المنفصلة
4. حقول هوية عامة (لا صيغة سعودية محددة) لدعم السياق اليمني
5. هيكل أكاديمي كامل (كلية/قسم/تخصص) غير موجود في النسخة الأصلية
6. معايير التقييم ديناميكية بالكامل حيث جدول evaluation_criteria قابل للتعديل من لوحة الإدارة (إضافة/حذف/إعادة توزين معيار دون نشر كود جديد)
7. لا وجود لصفحات مكررة
